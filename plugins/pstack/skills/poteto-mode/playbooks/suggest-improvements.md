### Suggest improvements

**You own the suggestions, not the implementation.** The deliverable is an Improvement Brief. It is not code, a design, or a task plan.

The run is read-only, like Investigation. No PR, no babysit, no `architect`, no prototype. No tickets or detailed plans unless the user asks for them.

1. Learn the product. Read its README, goals, and docs, then the code behind its main use cases. Run the **how** skill when a subsystem needs a real model. Use the product as a user when you can, through the project's verify skill or the driver skill. Name its users, main use cases, and value.
2. Find what already exists. Check implemented features, open issues, and existing plans for overlap, by user-facing name as well as code name. Mark each check existing, in progress, absent, or unverified. An access gap does not prove absence. Never present existing or planned behavior as new.
3. Find opportunities: unmet needs, friction, missing capabilities, new uses. Apply **principle-experience-first**. Implementation cost is not the first filter.
4. Write suggestions at three scales. Small improves existing behavior. Medium adds a significant feature. Large opens a new capability or direction. Scale is scope, not effort.
5. Give each suggestion its name, scale, current state, proposed change in product terms, user value, evidence (product facts, code locations, observations), and unknowns. Choose no internal architecture, estimate no effort, and write no tasks.
6. Write the Improvement Brief. Group it by scale. Separate evidence-backed suggestions from speculation. Name the suggestions worth an Investigation or a Prototype. The throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only suggestions`. Apply the **unslop** skill.
7. Present the brief and stop. A suggestion is not approval to build it. When the user picks one, re-route: Investigation to test a premise, Prototype to compare options, Feature to build it, Multi-phase or multi-PR plan for a staged program.

**Reply:** the Improvement Brief, its evidence, the assumptions, and the next questions worth investigating.
